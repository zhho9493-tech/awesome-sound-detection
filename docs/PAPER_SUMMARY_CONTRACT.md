# 论文总结字段规范 · Paper Summary Contract

此功能针对公共论文索引中的**每条记录**输出一个相同结构的总结对象，并展示于所有专题卡片及全库详情页。不是批量全文解读，也不能由自动抽取推断真实实验结果。

## 结构

```json
{
  "status": "abstract-extract",
  "basis": "public-abstract",
  "objective": "从公开摘要提取的研究目标原句",
  "method": "从公开摘要提取的方法相关原句，缺失时为空",
  "finding": "从公开摘要提取的作者报告结果原句，缺失时为空",
  "caveat": "自动摘录，不等于全文验证、独立复现"
}
```

当源记录缺少摘要时 `status=needs-abstract`，不从标题虚构目标、方法或结果。摘要已存在时仅选取原文句子，不改变数值、不伪造实验提升、不自动生成翻译或使用其他论文的数据。英文原句维持英文，以便核对。各字段的检索由确定性规则完成，可能漏选和错选；**该状态并非人工审核通过**。

## 数据更新路径

1. `scripts/paper_summary.py` 将每条记录摘要生成结构化摘录。
2. `scripts/build_paper_discovery.py` 合并两个公共来源并为全部记录写入 `summary` 字段。
3. GitHub Pages 构建时重新生成公共检索 JSON。专题页 `portal/topic.html` 和全库页 `portal/library.html` 使用同一个 `summary` 字段。
4. 若页面打开时索引尚未生成，页面可以退回仅展示摘要摘录/待补充状态，但这不是完整总结结果。

## 后续高质量总结升级标准

- 每篇论文人工或经受控流程全文阅读后，补充**问题、核心创新、方法流程、数据集、基线、关键指标、局限、代码链接、DAS/听漏等场景适用性**。
- 全文级总结应单独标记 `fulltext-reviewed`，必须关联可核查的章节、表格或图，以及审核人/审核日期，不能覆盖作者原文。
- 自动摘要摘录只是基础信息层，不等于经过核查的学术分析。
- 各方向使用同一论文 ID 链接到同一份总结，避免出现互相矛盾的多份总结。
